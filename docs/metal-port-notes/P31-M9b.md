## (a) Design

`crates/zkminer-prove-risc0/src/metal_start.rs`:
- `prewarm_mode()`: `Off` (`ZKMINER_METAL_PREWARM=0`), `Blocking` (`ZKMINER_METAL_PREWARM_BLOCKING=1`), or
  `Background` (the default). Pure parse `prewarm_mode_of`, tested; `PREWARM=0` wins.
- `start_eval_prewarm(po2)`: once per process, a thread `metal-eval-prewarm` runs the pipelines and then
  `metal_prewarm_segment_po2(po2, true)`. Its result goes into a `Mutex` + `Condvar` (`EvalPrewarm`).
  Background mode only.
  - `--benchmark`: started right after the budget plan (which fixes the segment po2), before the
    device line and the M7 graph preload.
  - IPC worker start: started by `start_first_job_prewarm`, as M9's thread was.
- `prewarm_before_benchmark(po2)` (call sites: `--benchmark`, IPC `Benchmark`, `Warmup`):
  - joins the pipeline build (`warm_up_pipelines` is a `OnceLock`);
  - runs the p254 ctrl prewarm **synchronously** (`ctrl_prewarm`, a `OnceLock`, so the IPC start thread
    and this share one commit);
  - returns, leaving the eval build running.
  - The other modes call M9's `prewarm_first_job`, unchanged in behaviour.
- `before_benchmark_program(name, po2, elf, input)`, called in `benchmark_program` before the stopwatch,
  power reading and samplers. `join_decision` (pure, tested) says what to do:
  - Nothing, when the build is done, for another po2, or not in Background mode.
  - Otherwise the probe `first_segment_po2`: `ExecutorImpl::run_with_callback` with the job's segment
    limit, stdout and stderr to sinks, and the callback stopping at the first segment.
    - Every non-final segment is a full segment of the limit po2. So the job has a segment of the
      prewarm po2 exactly when its first segment is one.
    - Cost: at most one segment of execution. Measured: 5-6 ms for fibonacci, 19-21 ms for
      memory-merkle (po2 20).
  - When the first segment is that po2, or the probe fails: join the build (`Condvar` wait) and log
    "joined ... waited X s". Otherwise log "starts at once" and run.
- `before_prove(po2, elf, input, seed)` in `run_proof`, before the retry loop. A Prove does not wait; it
  logs that its first segments may run the plain kernel. `ZKMINER_METAL_PREWARM_PROVE_JOIN=1` makes it
  probe and join like a benchmark program. This was measured and rejected as a default (IPC table
  below).
- Exit: nothing waits for the eval thread. `main` returns while Metal is still specializing.
  - Measured exit lag (results line on stdout to process exit): 0.020-0.026 s in every run, A and B,
    warm and cold (`exitlag.py`).
  - Archive writes are a temporary file renamed into place (risc0 `save_archive`), so an exit or a kill
    cannot leave a half-written archive (integrity test below).

Ordering with the GPU lock (step 3 of the brief):
- The ctrl prewarm takes `metal::exclusive()` for ~0.25 s. In `--benchmark` / IPC `Benchmark` /
  `Warmup` it now runs synchronously before the first program. So it never overlaps a measured program,
  and its commit is in place before the first wrap. Every first wrap in the A/Bs equals A's (wrap deltas
  0.000-0.010 s).
- The eval build holds no GPU lock (compile only), so it overlaps the ctrl commit and fibonacci's proof
  without contention.
- IPC start keeps M9's order: pipelines, then ctrl and eval side by side on background threads. A Prove
  at spawn waits at most for the ctrl hold, as before (M9 open issue 7 is unchanged).

Call-site changes in `main.rs`, all prewarm call sites:
- `start_eval_prewarm` after the `--benchmark` budget plan;
- `prewarm_first_job` -> `prewarm_before_benchmark` at `--benchmark`, IPC `Benchmark` and `warm_up`;
- `before_benchmark_program` in `benchmark_program`;
- `before_prove` in `run_proof`.

## (b) Building the set: `mac-build-aot`, `scripts/mac/build-metal-aot.sh`

`build-metal-aot.sh <worker> <out> [arch ...]`:
1. **Metallibs from the worker binary itself.**
   - It scans for `MTLB` headers with a consistent size and section table and writes each library.
   - In the 3.1 worker it finds 5: zkp `518b8340447b6bd8f2af27b0`, rv32im
     `6537b10c5bbfecb602451813`, recursion `4f52e4548cf1bde6059f182a`, keccak
     `0f98bbd23ec6976619e4b9b5`, groth16 `a99c12671ad7e657e98796b1`. keccak and groth16 are unchanged
     from 3.0's W7-Z1 set; zkp, rv32im and recursion changed with 3.1.
   - The Python digest is risc0's `parallel_digest`. It reproduces the W7-Z1 README's zkp digest
     `03b74d3e...` from the W7-Z1 dump.
2. **Kernel names per unit from risc0's `w7z1_dump_aot_inputs` tests.**
   - Built in `$RISC0_DIR` with `CARGO_TARGET_DIR=<zk-miner>/target/aot-dump` (dev profile;
     the metallibs do not depend on the profile) and run once per set of worker digests (cached as
     `target/aot-dump/dump-<key>`).
   - Every dumped metallib must have a digest the worker embeds. Otherwise it refuses: "RISC0_DIR is not
     the tree the worker was built from".
   - After a dump, the ~5 GB test build is deleted (`AOT_KEEP_DUMP_BUILD=1` keeps it). 337 MB of
     guest builds were left in the first version; `riscv-guest` is now in the cleanup list too.
   - recursion has no dump test. Its units (`recursion`, `recursion_splitrg`) come from
     `recursion-sys/src/lib.rs` and the embedded metallib that lists those kernels (`metallib_extract.py
     --list`).
   - The 3.1 dump gives the same unit list as W7-Z1's, without `keccakstrict` (a knob path, left out as in
     W7-Z1).
3. **Archives.** risc0's `build_archive.py`, one process per unit, `AOT_JOBS` (default 3) at once,
   largest first.
   - It builds this Mac's family only by default (`<worker> --metal-arch`); `AOT_ARCHES` overrides.
   - `--macos-min` is this Mac's major (27.0).
   - Then `SHA256SUMS`, `manifest.jsonl` and `WORKER` (the worker's sha256, arches, macOS), and the
     output directory is replaced in one rename.
   - A later call for the same worker and arches is a reuse ("already the set of this worker").

## (b) Install: `mac-install-worker` by default

`Makefile.mac`:
- New variables: `AOT` (default 1), `AOT_SRC`, `AOT_ARCHES` (now the families to build, default this
  Mac's), `AOT_VALIDATED` (default `applegpu_g17s`), `AOT_OUT` (`target/metal-aot`), `AOT_JOBS`.
- New target `mac-build-aot`.
- `mac-install-worker`, after copying the binary:
  - `AOT=0`: no set; a previous install's `metal-aot` is removed, and both are printed.
  - `AOT_SRC=<set>`: `install-metal-aot.sh <set> <worker> $(AOT_VALIDATED)` (as W7-M11).
  - default: asks the installed worker for its family.
    - If the family is in `AOT_VALIDATED`, it runs `build-metal-aot.sh` (the build script directly, not
      a recursive make, which cost a second 28 s cargo check), then `install-metal-aot.sh`.
    - Otherwise it prints "this Mac's GPU is X, offline archives are validated on hardware only for
      applegpu_g17s ... AOT_VALIDATED=X builds them anyway", removes a stale set, and the first start
      compiles at runtime.
  - A failed set build fails the install, with "AOT=0 installs without them". An install never
    silently ships without the set.
- `install-metal-aot.sh` now also refuses digest mismatches. The brief assumed it already did; it only
  checked `SHA256SUMS`.
  - Every archive's digest field must be among the worker's embedded metallibs
    (`build-metal-aot.sh --worker-digests`).
  - Otherwise it exits 1 ("digest mismatch ... rebuild the set for this worker") and leaves the
    installed set as it was.
  - `AOT_SKIP_DIGEST_CHECK=1` is for the fake-worker tests only.

## Knobs

- `ZKMINER_METAL_PREWARM_BLOCKING=1`: M9's blocking prewarm (measured identical to A).
- `ZKMINER_METAL_PREWARM=0`: no first-job prewarm (pipelines only; wins over the other knobs).
- `ZKMINER_METAL_PREWARM_PROVE_JOIN=1`: a Prove also probes and waits (measured +3.4 / +6.2 s cold; off).
- Install: `AOT=0`, `AOT_SRC=<set>`, `AOT_ARCHES`, `AOT_VALIDATED`, `AOT_OUT`, `AOT_JOBS`;
  `build-metal-aot.sh`: `RISC0_DIR`, `AOT_DUMP_TARGET`, `AOT_MACOS_MIN`, `AOT_KEEP_DUMP_BUILD`.
- Run time: `ZKMINER_METAL_AOT=0` (W7-M11) ignores an installed set.

## Tried and rejected

- **A Prove that waits for the in-flight build** (`ZKMINER_METAL_PREWARM_PROVE_JOIN=1`): +6.22 s (Prove at
  spawn) and +3.40 s (at 3 s) cold, 7/7, to save ~0.13 s. Kept as an opt-in knob only.
- **`RISC0_METAL_RV32IM_EVAL_FC=wait` semantics for the first job** (brief option 2). Not used:
  - the mode is read from the process environment on every eval call and applies to every domain;
  - fibonacci's po2 15 segment would then wait for its own cold specialization (~6.5 s), the opposite of
    the goal;
  - setting it around one job means `set_var` while other threads run.
  - The existing join (`metal_prewarm_segment_po2(po2, true)` on the in-flight build, here through our
    own condvar) fits, so no risc0 API is proposed.
- **Running the AOT build as a recursive `make mac-build-aot` from `mac-install-worker`**: the extra cargo
  check cost 28 s per install (58.9 s vs 32.6 s total). Replaced by a direct script call.

## Deviations

- `install-metal-aot.sh` did not check digests (the brief said it did). The check was added.
- `AOT_ARCHES` changed meaning: it was the validated list (W7-M11) and is now the families
  `mac-build-aot` builds, per the brief. The validated list is `AOT_VALIDATED`.
- The IPC `Warmup` became non-blocking like the benchmark (pipelines + ctrl synchronous, eval in the
  background). Its own proof is a small fibonacci that does not use the po2 20 kernel, and a blocking
  Warmup would delay the dispatcher's first job by up to 6.6 s cold.
- The dump tests run as part of a user's install (they load each library on the GPU; no GPU work).

## Open issues

1. **First exec of a freshly built or copied binary costs ~1.4 s once** (3.66-3.77 s against 2.3 s for
   the next runs; seen for B in `smoke/` and `smokefinal/`). That is the OS's first page-in /
   signature check of the 180 MB binary, not this item. The A/Bs discard one launch per arm for it.
2. The dump tests (~5 min of compile, ~5 GB transient disk) run on a user's first install and after
   every risc0 kernel change. Shipping the dump's `units.jsonl` with the release, or a worker flag that
   prints its units (kernel names are in risc0's sys crates), would remove that build. The latter is a
   risc0 API, which this item may not add: proposed `risc0_*::metal::aot_units() -> Vec<AotUnit>` per
   circuit crate, exported in non-test builds.
3. **4 GiB budget: risc0 3.1's Groth16 prover takes 4.235 GB with ~60 MB of headroom.** A wrap failed
   once in the unmodified A (`ab/4g/mm.warm.A.1`) when 65 MB was still allocated before it. This belongs
   to risc0 / the 4 GiB tier (P31-19 open issue 3 is the keccak variant of it).
4. The cold IPC Prove B-A of +0.024 / +0.029 s (6/7) sits at the edge of the session spread. Not
   explained; a longer IPC A-vs-A run would settle it.
5. Only applegpu_g17s is validated. Other families install no set by default and compile at first start
   as before (~76-81 s here, longer on smaller GPUs).
6. A cold OS shader cache still costs ~6 s in a benchmark whose programs reach the prewarm po2: the
   memory-merkle-only benchmark, or the full suite from sha256-chain on. That wait is now outside every
   stopwatch and overlaps fibonacci in the full suite. Removing it needs Metal to keep the
   specialization (W7-Z1: no archive does).
7. Not measured on a real 16 GB Mac or other GPU core counts. The full six-program suite was not run
   cold (fibonacci goes first, so it would save ~2.3 s of wall).
